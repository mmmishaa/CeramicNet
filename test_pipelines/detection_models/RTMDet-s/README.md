# Проверка RTMDet-s

[rtmdet_s_test.ipynb](rtmdet_s_test.ipynb) запускает лучшие веса после полного
обучения и сохраняет отдельные отчёты:

- **val:** 51 stamps + 94 негатива, без тренировочных фото;
- **stamps:** все 254 фото с разметкой, включая 203 тренировочных — для просмотра рамок.

Используется `v3_seed42_reserve80_active15` из универсального пайплайна и общий COCO-оценщик.
Нового случайного разделения нет. Порог переносится с val выбранного checkpoint.
41 пересечение предметов между train/val (включая 8 между негативами) остаётся
свойством исходного split; общих файлов и SHA256 нет; независимого test пока нет.

## Запуск

Сначала выполнить [обучение RTMDet-s](../../../train_pipelines/detection_models/RTMDet-s/README.md)
на 50 эпох. В тестовом ноутбуке выбрать ядро **CeramicNet RTMDet (CPU)**:
последний завершённый полный опыт выбирается автоматически, пробные веса
после одной эпохи и веса с другого split не выбираются. Можно явно указать `TRAIN_RUN`.
Fingerprint и хеши всех пяти файлов протокола сверяются с metadata обучения;
порог с другого val не принимается. Старые веса v2 для оценки текущего v3 не подходят.

Из корня CeramicNet также доступен отдельный скрипт:

```bash
.venv-rtmdet/bin/python test_pipelines/detection_models/RTMDet-s/test_rtmdet_s.py \
  --config runs/ИМЯ_ОПЫТА/configs/rtmdet_s.py \
  --checkpoint runs/ИМЯ_ОПЫТА/train/best_coco_bbox_mAP_epoch_НОМЕР.pth \
  --validation-metrics runs/ИМЯ_ОПЫТА/val/metrics.json \
  --images /путь/к/Клеймы \
  --scope val --output runs/ИМЯ_ОПЫТА/test/val
```

Для всех stamps заменить `--scope val` на `--scope stamps` и выбрать новую
папку `--output`. Скрипт читает `.pth` через MMDetection, экспорт ONNX не нужен.
По умолчанию использует CPU; для совместимого CUDA-окружения есть `--device cuda:0`.

## Результаты

В каждой папке сохраняются `gallery.html` и все картинки с рамками,
`predictions.json`, `metrics.json`, `timing.json`, `benchmark_results.csv`,
`annotations.json` и `run.json`. Зелёные рамки — разметка, красные — модель.

CSV содержит имя набора, число изображений train/val, хеш разметки и checkpoint,
фиксированный порог, качество и скорость. Загрузка модели, прогрев и чтение
изображения с диска не включаются во время обработки.

Общий ONNX-бенчмарк YOLO из `main` использует другое случайное разбиение и свой
оценщик. Его строки в общей таблице не изменяются. Для прямого сравнения моделей
нужно заново оценить их на одном сохранённом val общим оценщиком; метрики на
всех stamps с тренировочными кадрами не являются независимым результатом.

Веса и фотографии в Git не включаются, отчёты находятся в игнорируемой папке `runs/`.


## Результат полного обучения, 24 октября 2026

Завершены 50 эпох на v3 с восстановлением состояния после остановок. Выбран
checkpoint **49-й эпохи** по максимальному native val mAP. Общий оценщик на
145 val-фото: **mAP50–95 = 0.6536**, **AP50 = 0.8481**, **AP75 = 0.6932**.

При фиксированном пороге 0.5: precision **81.13%**, recall **82.69%**, F1 **81.90%**;
ложные срабатывания есть на **8 из 94** негативных кадров. Порог 0.84, выбранный
на val для precision ≥ 90%, даёт precision **90.00%**, recall **51.92%** и
ложные срабатывания на **2 из 94** негативов. В галереях и CSV используется 0.84.

Сводка с хешами протокола и checkpoint: [results_v3.json](results_v3.json).
[benchmark_results_v3.csv](benchmark_results_v3.csv) содержит отдельные строки
val и всех stamps. Последние включают тренировочные кадры; не используйте эту
строку как независимую оценку качества. Фотографии и веса остаются локально в runs/.
